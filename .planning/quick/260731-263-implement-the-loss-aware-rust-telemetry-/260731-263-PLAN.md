# Quick Plan 260731-263: Host capture-begin, batch sequence, and terminal loss

Close the remaining Linux-host evidence gaps before building any Rust client
bridge. This split owns only the real NvFBC capture-begin timestamp, an
accepted host batch identity, and a terminal loss/completion record.

## Scope and safety boundary

- Parent deliverables are patches `0012` and `0013`, one verifier, and README
  documentation. Nested source edits are working material only; never create
  nested commits or stage `upstream/kyber-desktop`.
- Preserve all existing patches, especially the user-owned untracked
  `0003-linux-zlib-pic.patch`, plus Phase 01/Phase 10 work and `log/`.
- Do not restart or deploy the current Linux user service. No client, GUI,
  storage, codec policy, audio, or multi-monitor files are in scope.
- `capture_begin→acquired` is labeled
  `host_capture_to_cuda_surface_ready`: it includes the NvFBC grab and the
  existing same-GPU device copy. It is not advertised as scanout age or pure
  GPU capture time.

## Task 2: Sequence accepted batches and disclose terminal loss

**Files**

- `upstream/kyber-desktop/kysdk/kymedia/kyavservice/src/metrics.rs`
- `patches/kyber/0013-kymedia-host-evidence-sequence.patch`

**Action**

- Allocate one `sequence` before each `MetricsForwarder::try_forward` attempt.
  Append `telemetry_forwarder_sequence` to the outgoing vector only for that
  attempt, without reordering or modifying the source entries. On rejection,
  use that exact sequence in existing coherent cumulative loss state.
- Track `last_accepted_sequence` atomically only after `try_send` accepts the
  vector. Keep `last_attempted_sequence` represented by the existing sequence
  counter. Saturate when converting to the wire's `i64`; never wrap or panic.
- Pass the same `Arc<ForwarderState>` to `forward_task`. The callback closure
  owns the sender; once it is removed/dropped, the channel closes. The forward
  task first drains all accepted vectors in order, then obtains one coherent
  final state snapshot and sends a direct terminal MessagePack vector through
  the still-open KyCom metrics endpoint.
- The terminal vector contains:
  `telemetry_forwarder_terminal=1`,
  `telemetry_forwarder_final_sequence`,
  `telemetry_forwarder_final_accepted_sequence` (zero explicitly means none),
  and the coherent cumulative loss tuple when nonzero. It is not assigned a
  normal producer sequence and cannot be confused with frame evidence.
- Mark the state terminal-reported only after the direct KyCom send succeeds.
  A send/serialization/transport failure is logged as terminal unconfirmed;
  no local success is fabricated. The later client bridge is required to mark
  a disconnected source without this terminal vector as
  `producer_terminal_unconfirmed`.
- Add tests for: sequential accepted identity; accept/reject/recover identity
  and loss ranges; simultaneous writers; first accepted sequence greater than
  one; no accepted batches; final rejection with no later callback; channel
  drain before terminal; direct terminal send failure; cumulative terminal
  tuple coherence; and no double counting between recovery and terminal.
- Generate `0013` from Kymedia
  `e80eb6bb347ed0e378ae46a86f67ada2aa6079da` after applying prerequisites
  `0008` to its txproto worktree and `0009-kymedia-host-telemetry-forwarding.patch`
  to Kymedia, with no nested commit or gitlink movement.

**Verify**

- From the exact Kymedia tree, run:
  `cargo test --locked -p kyavservice metrics::tests`
  with the project Rust `1.89.0` toolchain and the prerequisite-patched
  txproto path used by the normal Kymedia build.
- `cargo fmt --check -p kyavservice` and the targeted
  `cargo clippy --locked -p kyavservice --tests -- -D warnings` pass, or the
  verifier records an upstream-only warning with changed code warning-free.
- Tests prove a final rejected attempt appears in the direct terminal vector
  even when no later native callback occurs, and that the terminal vector is
  sent only after accepted batches drain.
- Clean replay applies `0009`, snapshots the prerequisite Kymedia baseline,
  applies `0013`, runs tests, reverse-applies `0013`, and proves byte identity
  with that baseline while all recursive HEADs stay pinned.

**Done**
