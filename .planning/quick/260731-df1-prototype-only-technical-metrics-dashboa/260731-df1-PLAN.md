# Quick Plan 260731-df1: Prototype technical metrics cards

Add an honest glanceable dashboard to the existing AppKit launcher, using only
the telemetry Kyber already writes. Keep the raw logs and unchanged `kyclient`
available, then package and smoke-test the arm64 app.

## Scope boundary

- Modify only `prototype/macos/ReplayDesktopLauncher.swift`; reuse
  `scripts/package-macos-gui.sh` and `scripts/verify-gui-spike.sh` unchanged.
- Do not touch `patches/kyber/0010-*`, `0011-*`, `0014-*`,
  `scripts/verify-vlc-rs-video-path-bridge.sh`, or nested Kyber sources.
- Do not consume configured codec/chroma or requested settings as measured
  telemetry. If an event does not prove a value, render `Unknown`.
- Preserve all unrelated tracked, staged, untracked, nested-worktree, and
  `log/` changes. Build the package from a separate clean checkout/worktree at
  the dashboard commit.

## Task 1 (tracer): Parse existing JSONL events into three live cards

**Files**

- `prototype/macos/ReplayDesktopLauncher.swift`

**Action**

- Add a small in-memory `MetricsJSONLReducer` and `CurrentMetrics` model beside
  the existing `TailCursor`. Accept only the current `metrics.json` records:
  - `raw_metric/type=video` with `source_id`, `pts`, `ts`, and the existing
    `acquired`, `encoding`, `encoded`, `sent`, `received`, `decoding`,
    `decoded`, `prepared`, `displayed`, or `skipped` event.
  - `raw_metric/type=network_local|network_remote` with `rtt_micros`,
    `packets_lost`, and `dropped_packets`.
  - `raw_metric/type=network_ping` with `offset_micros` and `delay_micros`.
- Correlate video events by `(source_id, pts)` in a bounded recent-frame map.
  Derive only same-clock, nonnegative durations: Host `acquired → encoded` and
  `encoded → sent`; Client `received → decoded` and `decoded → displayed`.
  Show the latest terminal frame outcome as `Displayed`, `Skipped`, or
  `Unknown`. Display network local/remote RTT, ping delay, packet loss, and
  dropped-packet counters directly from the latest valid records.
- Build three compact AppKit cards titled `Host`, `Network`, and `Client`
  between session status and the existing raw telemetry view. Initialize every
  row to the literal `Unknown`; format known durations from microseconds as
  milliseconds without implying more precision than the source.
- Feed each newly tailed `metrics.json` byte chunk to the reducer while still
  appending the exact decoded bytes to `telemetryView`. Keep an incomplete-line
  buffer across reads, ignore malformed/unsupported JSON lines, and never
  rewrite or filter the raw files or transcript.
- Reset reducer state and all card labels to `Unknown` when a new child starts
  and when it terminates, so a disconnected or new session cannot display a
  prior session as current. Keep the existing 0.5-second timer, child process,
  tail cursors, Clear behavior, and raw log paths.
- Extend the existing `--self-test` with JSONL fixtures proving initial/reset
  Unknown values, chunk-split lines, out-of-order same-frame events, valid
  host/client deltas, `-1` network sentinels, malformed lines, skipped frames,
  and rejection of negative deltas. Do not add a separate native bridge or
  telemetry service.

**Verify (automated)**

- On macOS, compile with the existing package command:
  `xcrun --sdk macosx swiftc -parse-as-library -target arm64-apple-macos15.0 prototype/macos/ReplayDesktopLauncher.swift -framework AppKit -o /tmp/ReplayDesktopLauncher-df1`.
- `/tmp/ReplayDesktopLauncher-df1 --self-test` passes and reports the metrics
  fixture assertions in addition to the existing launcher argument matrix.
- `file /tmp/ReplayDesktopLauncher-df1` reports arm64 Mach-O.

**Done**

- A real session's existing video/network JSONL updates the three cards, absent
  evidence remains `Unknown`, and the complete raw telemetry view still works.
