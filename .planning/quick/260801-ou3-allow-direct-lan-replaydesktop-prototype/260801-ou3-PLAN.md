# Quick Plan 260801-ou3: Allow direct-LAN ReplayDesktop connections

Open the already-correct ReplayDesktop endpoint through the host firewall for
prototype testing. Keep kycontroller on its existing IPv4 all-interface bind,
make no repository or Kyber configuration changes, and prove only the
reachability that can be observed from the available Mac builder.

## Scope boundary

- Change only the live, persistent UFW policy. Do not edit Kyber code,
  `/home/finn/.local/share/replaydesktop/kyber-spike.toml`, service definitions,
  routing, NAT, or network interfaces.
- Add source-unrestricted IPv4 rules for exactly port 8080 over TCP and UDP;
  do not reset UFW, reorder/delete existing rules, or open any other port.
- Preserve every tracked, staged, untracked, and nested-worktree change. This
  is a runtime-only quick task and should not create a repository commit.

## Task 1 (tracer): Open port 8080 and prove the live LAN path

**Files**

- `/etc/ufw/user.rules` through the `ufw` CLI only; never edit the managed file
  directly.

**Precondition**

- UFW is active with the observed default/drop input policy, and kycontroller
  is still the process listening on TCP `0.0.0.0:8080`; stop and report if
  either fact has changed before applying rules.

**Action**

- Record `sudo ufw status numbered`, the `ufw-user-input` portion of
  `sudo nft list ruleset`, and `ss -lntup` entries for port 8080 before the
  change so existing firewall rules and listeners remain attributable.
- Add the two idempotent persistent rules with the UFW CLI: one
  `allow proto tcp from 0.0.0.0/0 to any port 8080` rule and one equivalent
  UDP rule. Give both the comment `ReplayDesktop prototype`. Do not attach the
  rules to a named interface: the explicit prototype requirement is every host
  interface and every IPv4 source.
- Re-read UFW status and the live nftables ruleset. Confirm that both exact
  protocol/port rules are active in `ufw-user-input`, with no broader port or
  protocol allowance introduced. Confirm kycontroller still has TCP
  `0.0.0.0:8080` in `LISTEN`; record any UDP 8080 socket as supporting evidence
  without changing Kyber if no UDP socket is currently exposed.
- If the Mac builder has a route to the `192.168.33.0/24` LAN, run a bounded
  TCP connection probe from that Mac to `192.168.33.42:8080` and
  `192.168.33.64:8080`. Record each attempted address and result. At least one
  routed address must connect; if the builder cannot reach this LAN at all,
  record that external topology limitation and do not claim remote LAN
  reachability from the local firewall checks alone.

**Verify (automated)**

- `sudo ufw show added` contains separate IPv4 `8080/tcp` and `8080/udp`
  source-unrestricted rules, and `sudo ufw status numbered` reports both as
  active `ALLOW IN` entries.
- `sudo nft list ruleset` shows TCP destination port 8080 and UDP destination
  port 8080 accepted through `ufw-user-input` before the terminal drop path.
- `ss -H -ltnp '( sport = :8080 )'` reports kycontroller on
  `0.0.0.0:8080`.
- When the Mac builder has LAN routing, `/usr/bin/nc -vz -G 3
  192.168.33.42 8080` and `/usr/bin/nc -vz -G 3 192.168.33.64 8080` are run
  there and every route-reachable address succeeds.

**Done**

- UFW persistently permits all-source IPv4 TCP and UDP ingress on port 8080,
  the existing all-interface kycontroller listener is unchanged, and remote
  TCP reachability is either proven from the LAN-reachable Mac builder or
  explicitly left unclaimed with the builder routing limitation recorded.
